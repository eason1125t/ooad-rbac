= 后端第一切片：组织、人员与账号基础
:toc:

== 基线与当前状态

用户已确认link:development-baseline.adoc[开发基线v2]并授权将当前规划/骨架上传指定GitHub。本文件准备后续后端、API和数据库设计的第一切片；尚未实现以下管理API、迁移或完整业务，不修改已应用V1。
顺序为需求/字段与契约→测试设计→新增Flyway迁移→服务/安全适配→联调与Apifox回读。当前8操作仍是实际API；本文件是设计任务单，不是第二份OpenAPI或可执行DDL。

== 第一切片范围

* 组织树及组织新增、修改、移动、停用；组织类型/层级/负责人规则按v2，移动先影响预览。
* 员工分页、详情、新增、资料修改、主要组织归属；员工、账号分离，岗位不自动产生角色。
* 账号显式建号、启停、平台重置密码、本人改密/强制改密；最后平台管理员保护，旧身份版本撤销。
* 最小审计持久化与管理权限点，保证上述成功写事务有审计；业务管理员只读合法范围，不能借演示入口获得管理写能力。
* 人员变动的原子撤旧/授新命令在角色/委派模型完成后接入；第一切片不得提供一个只改岗位却遗漏角色处置的伪完成接口。可先实现不触发人员变动的资料编辑。

暂不执行真实员工导入、不实现完整角色委派写入、OA/PMIS审批、权限缓存或RBAC1–3。不同功能逐切片补齐，不将未实现API暴露为成功。

== 设计清单与产物

. 在requirements/traceability中拆分用例和明确权限点；补齐组织、员工、账号字段约束、分页/搜索/排序、错误与版本语义。
. 先在contracts/openapi.yaml定义对应操作、请求/响应、400/401/403/404/409/422/429/503、CSRF及权限元数据，运行契约校验并生成TS；实现前完成测试设计。
. 新增迁移准备组织闭包、负责人关联、员工版本/来源绑定、账号强制改密、审计及权限目录种子；组织唯一/环校验、账号员工一对一、索引与回填均在真实MySQL验证。具体迁移序号按未应用的下一版本确定，V1不重写。
. 明确identity公开读写接口、administration组合事务、authorization统一检查及audit公开写入口；保留构造器注入与模块依赖测试，不让权限核心依赖HTTP或业务表。
. 先实现平台最小管理链再接前端；后续角色/委派模型纳入按应用的业务管理员范围约束，不能以账号名称判断超级管理员或关闭CSRF。

== 必须验证的完成条件

* 空库与已有V1库升级均通过；二次迁移无漂移，真实FK/唯一/CHECK拒绝非法记录，字典/ER从Flyway同步生成。
* 未登录401、缺权限403、未知接口默认拒绝、CSRF必需；真实Redis Session及账号停用/改密撤销通过，基础设施失败503。
* 组织环、非法层级、超8层、启用子节点/在职员工阻止停用；同父重名、重复账号、版本覆盖冲突拒绝。
* 新账号不自动获得业务角色；业务管理员不能编辑本人授权、组织资料或重置他人密码。
* 写入与审计一起提交，失败无半完成状态；测试不使用原始人员信息，日志无秘密。
* 后端verify、三端verify、文档渲染及相关真实MySQL/Redis集成通过；契约同步指定Apifox项目并回读，报告区分实际执行/未实现/跳过。

下一个切片再完成单应用角色、人员/角色维护责任、两份可委派清单及人员原子换角；必须证明管理员失权/交接不改变其他员工已经成立的授权。
