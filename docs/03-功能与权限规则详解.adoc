= 功能与权限规则详解
:toc:

本文件整理用户已确认的v2规则，并说明当前实现。尚未实现的业务与扩展统一见10；完整定稿原文见link:历史资料/02-开发基线定稿原文.adoc[历史基线]。

== 先区分五个概念

[cols="2,5,4",options="header"]
|===
|概念 |含义 |不会自动产生什么
|组织/岗位 |行政归属和人员资料 |不会自动产生角色、审批资格
|账号 |登录主体；普通账号关联一名员工 |建号不会自动分配业务角色
|角色 |某应用内的一组权限与范围 |角色名不产生平台资格；当前没有继承
|管理员委派 |平台授予某账号在某应用内的管理资格和上限 |不会给管理员本人授予业务权限
|人员维护责任 |某应用中由哪名管理员维护此人的授权 |不是员工权限生效条件
|===

平台管理权也不自动提供读取OA/PMIS业务记录或代批的能力，业务访问仍需显式业务角色。历史引导角色是受保护的兼容例外，不作为普通业务模板。

== 五个工作区

[cols="2,5,4",options="header"]
|===
|工作区 |当前功能 |限制
|工作台 |真实账号/人员统计、当前身份与应用范围、近期审计和任务入口 |没有待审批/导入/到期提醒接口，不造统计
|组织与用户 |组织设置、人员档案、登录账号；资料、启停、建号、重置、调岗；每应用授权与来源 |身份写入仅平台；业务管理员只读本应用责任人员并维护其授权
|角色与授权 |基本信息、权限配置、成员三个标签；有效期、预览、授予/撤回、专用角色交接 |通用角色由平台维护；业务管理员受责任和完整适用范围限制
|应用与资源 |管理应用信息、已登记权限目录、管理员与范围 |目录只读；应用/资源/权限点CRUD尚未开放
|操作审计 |真实分页、目标、动作、前后差异、traceId |当前仅平台读取，无编辑、删除、导出或业务管理员范围审计
|===

== 平台、业务管理员和普通用户

平台可以为同一应用配置多名业务管理员，同一账号也可被独立委派多个应用。每份委派含人员范围、可授通用角色白名单、业务权限/数据范围上限、启用状态和有效期。业务管理员不能任命下级管理员，也不能改变自身委派。

同一应用每名普通用户至多一名当前责任管理员，不同应用可以不同。组织范围重叠时不自动转移人员责任。业务管理员只能维护自己负责且在范围内的人员，不能给自己或其他业务管理员改业务角色，也不能通过编辑含管理员成员的专用角色间接提权。

普通用户只按自己的有效业务角色访问业务，不因为其管理员离职而被撤权。平台可以处理待接管责任；未接管不是暂停员工访问。

== v2：新增权限受双上限，已有授权独立

令P为操作者当前有效业务权限，D为平台委派上限，则本次新增/扩大授权的上限为C=P∩D。检查同时包含动作、应用、数据范围和时间扩展。

* 新授角色：检查完整角色权限定义，不能只检查现在已经生效的权限。
* 修改角色或授权：检查新增权限、扩大范围或延长有效期；原来保留的合法部分不追溯裁剪。
* 纯撤回/缩小：仍检查管理资格、人员责任和范围，不要求操作者也拥有被撤回的业务动作。
* 管理员个人失权、离职、委派到期或接管人业务权限较小：不修改员工原有角色和授予来源。

例如员工已合法拥有导出，新接管管理员只有查看：员工仍可导出；新管理员可以在合法管理范围撤回旧导出，却不能重新授予自己没有的导出。不能用停用共享角色来代替“撤回管理员本人角色”，前者会明确影响所有持有人。

== 角色类型与共享影响

[cols="2,4,5",options="header"]
|===
|类型 |维护者 |规则
|PLATFORM |平台 |归属admin；平台权限不能混入普通业务角色
|COMMON |平台 |单业务应用的通用角色；业务管理员仅在白名单和当前上限内分配
|SCOPED |指定业务管理员/平台 |绑定维护人和人员适用范围；维护者须覆盖完整范围及全部成员责任
|LEGACY |工程兼容保护 |历史跨应用引导角色，不允许作为普通可编辑模板
|===

业务管理员本人使用平台维护的通用角色，避免“编辑自己的专用角色”绕过自授限制。角色编码全局唯一、稳定且不可复用；同应用、同类型、同责任域内规范名称防重。

当前RBAC0只有用户—角色、角色—权限关系，没有用户直配权限、角色优先deny或角色继承。多个有效来源取并集；撤回一个来源不应抹掉其他来源。主动停用角色/权限/应用或关系到期，才按目标授权事实使相应权限失效。

== 人员范围、数据范围与有效期

管理人员范围用allCompany或多个组织节点及各自includeDescendants表达。业务数据范围独立采用：

[cols="2,6",options="header"]
|===
|范围 |含义
|SELF |目标用户本人的业务记录，不是管理员本人的记录
|ORG |指定组织节点，不含下级
|ORG_SUBTREE |指定组织及其下级，保留子树模板语义
|ALL |当前业务应用全部记录，不代表全平台所有数据
|===

组织目录可展示必要祖先名称，但不代表这些祖先中的人员可管理。相同权限点的多个角色范围取并集；SELF与有限组织范围不能随意互相替代。当前范围算法已实现，OA/PMIS业务记录SQL过滤尚待实现。

成员、角色权限和委派分别有自己的[from,to)，开始包含、结束不含，null表示无界。界面按北京时间录入/展示，服务端和数据库使用UTC毫秒。目标授权期限允许长于授予者任职期限；目标仍按自身有效期失效。

== 组织、人员和账号生命周期

组织是唯一总公司根，下面可以有分公司或部门，部门可以有子部门，最多8层。分公司不能挂到部门下；禁止环、跨根、同父重名。有启用子组织或在职人员时不能直接停用。

每名员工一个主要组织，可无账号；普通账号必须关联员工且一对一。岗位和负责人只是资料。员工普通编辑只改姓名/电话；组织或岗位变化走“调岗换角”。表单会回显原角色便于显式保留或移除，提交内容是各应用完整新集合，不能把回显视为自动恢复旧授权。

调岗将本人组织/岗位、各应用角色、KEEP/RETIRE任职和责任变更放进同一预览/事务。失败全部回滚。离职停用会停用本人账号、撤回本人业务成员关系与必要任职，使旧会话失效；重新启用人员不会自动恢复账号或角色。

专用角色交接只改维护归属及必要责任，保留成员、有效期、授予历史。员工有多个专用角色时允许逐步交接，期间责任可AWAITING，最后一致后CURRENT。委派续期或重新启用不自动收回待接管人员，平台须明确指定。

组织移动是独立影响多人范围的操作。当前无授权/范围引用时可预览提交；存在引用时保护性409拒绝，完整影响分析未实现。它不同于某个人调岗，不可直接改库绕过。

== 登录、安全与审计

无自助注册、短信或第三方登录。用户名规范化后为3–64位小写字母/数字及._-；唯一且不可修改/复用。demo账号口令1234仅限显式隔离演示；正常密码至少12字符、最多72个UTF-8字节。

正常建号/重置仅返回一次随机临时密码，首次只能改密/退出等必要接口；改密后旧会话失效并重新登录。演示账号使用独立策略，不把1234作为正式默认密码。平台不能停用或撤销最后一个有效平台管理员。

会话空闲30分钟、绝对2小时，允许多设备；退出只撤销当前会话，改密/账号停用通过身份版本使全部旧身份失效。登录账号连续失败5次暂缓15分钟，IP每分钟最多30次尝试；超限429，设施故障503，不永久锁号。

管理写与审计同事务。审计记录目标ID、版本、状态和差异，不记录姓名、电话、密码、Cookie、令牌或原始Excel行。数据事实提交与Redis响应保存不是跨系统原子事务；503或网络失败后应先回读结果。
