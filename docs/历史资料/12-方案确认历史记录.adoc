== 逐项记录

=== Q001：业务管理员是否维护本应用的普通角色

状态：已确认B（2026-10-25，用户答复“b”）；仅设计决定，管理写功能未实现。
前置已确认：业务管理员可登录平台；管理应用及人员组织范围由平台指定，可选全公司；不得自行扩大管理范围，可委派权限上限由平台控制。

方案A：业务管理员只给范围内人员分配/撤销平台预先建好的角色；普通角色及角色权限均由平台维护。
方案B（推荐）：业务管理员可在被委派应用中维护普通业务角色及其权限，并给范围内人员分配/撤销角色；角色权限不得超过平台指定的可委派权限上限。平台保留账号/组织维护、应用管理员任命、委派范围和权限目录维护职责。

设计影响：决定管理权限点及角色写接口的职责；选择B后还需逐项确定角色归属、共享角色修改的影响范围、自我授权和多人管理规则，不能把角色编辑视为普通成员授予。
用户决定：采用B。业务管理员可维护被委派应用的普通业务角色及其权限，并在平台指定人员范围内授予、撤销角色；不得超过平台指定的可委派权限上限。账号/组织维护、权限目录维护、应用管理员任命及委派范围设置仍由平台负责。

=== Q002：共享角色的修改如何避免影响范围外人员

状态：已确认推荐方案（用户答复“同意”）；仅设计决定，管理写功能未实现。
前置：Q001已选B；人员管理范围不能被角色权限修改绕过。

推荐：普通业务角色区分应用通用角色与组织专用角色。通用角色由平台维护定义；业务管理员仅能将获准分配的通用角色授予自己范围内人员。业务管理员可创建组织专用角色，其人员适用范围必须在自己的管理范围内；修改角色定义/权限或停用角色时，也必须覆盖该角色完整适用范围，并符合可委派权限上限。授予专用角色时，目标人员须同时在管理员人员范围和角色适用范围内。

这里的角色适用范围限制可授予的人员，不等于OA/PMIS业务记录的数据可见范围；组织层级与角色范围不产生RBAC角色继承。角色范围的创建/调整校验、多人维护资格及调岗后的已有成员处理仍在后续问题中单独确认。
示例：OA审批员可由平台维护，工程分公司的管理员可将获准分配的该角色授予工程人员，但不能改动全公司共用角色的权限；其可另建仅适用于工程分公司范围的“工程审批员”，在可委派上限内维护。
代价：可能存在不同组织职责相近的专用角色；通用角色减少重复定义，范围内角色满足局部差异，界面必须显示应用与适用范围。
用户决定：采用上述方案。应用通用角色由平台维护；组织专用角色由管理范围覆盖该角色完整适用范围的业务管理员维护。业务管理员只能将获准分配的通用角色授予其范围内人员；专用角色的人员适用范围必须位于其管理范围内，授予时同时校验两类人员范围。角色定义修改仍受可委派权限上限约束。

=== Q003：平台如何配置业务管理员的可委派上限

状态：已确认两份清单，且用户明确增加本人权限与下属权限上限约束；仅设计决定，尚未实现。
前置：Q001允许维护专用角色并分配，Q002区分通用角色与专用角色。

已确认规则：在每个管理员的每个应用委派中，分别设置“可分配的通用角色清单”和“可配置的业务权限点清单”。两类清单均由平台显式设置，默认不授予；新增角色/权限点不自动扩张既有委派清单。新增/扩大授权时上限为平台委派权限集合与管理员本人当前有效业务权限的交集。通用角色还须命中通用角色清单；专用角色继续校验Q002的适用范围。Q003曾按下属权限始终不超上限解释，现已被Q004明确修正为授予时约束，不进行运行时持续裁剪。

纠正：前一版“管理员本人拥有与否不影响授权上限”的建议已被用户明确覆盖；平台委派与本人拥有现在必须同时满足。管理资格仍不从业务权限自动推导，拥有某项业务权限也不等于可以委派它。

示例：OA管理员获准分配OA普通员工、OA审批员，权限点上限只包含查看、新增、编辑、审批；不能借通用角色或专用角色给他人授予未委派的导出权限，也不能任命应用管理员。
界面位置：沿用“应用与资源→应用详情→管理员与范围”，人员组织范围、通用角色清单和权限点上限集中配置，不新增一级菜单。
后续方案：责任管理员归属、多角色合并、授予后独立生效、时间窗口与数据范围规则已纳入development-baseline的D01、D04–D06和D08，并随v2统一确认。
用户决定：同意两份清单，并明确本人权限上限/下属不超上限；其余细节由协作者推荐后统一确认。

=== Q004：管理员人员变动不影响他人，变动人员只替换本人角色

来源：用户说明管理员可能调岗或人员更换，其他员工照旧；管理员失权不得影响其已授出权限，人员变动直接撤回本人旧角色再赋新角色。
调整决定：采纳授予后独立生效，撤销v1中下属权限实时与管理员权限取交集、跟随暂停/恢复及授权期限不得超过管理员期限的推荐。新增/扩大授权仍须满足操作者当时本人权限与平台委派上限；历史合法权限不追溯裁剪，责任接管本身不改已授关系。
人员变动只改目标人员自己的角色和应调整的管理委派，不修改共享角色定义或他人关系。实现建议为单事务完整角色集合替换，校验失败回滚旧状态；管理员离任后维护责任由平台接管或转交，不影响用户业务访问。纯撤销仅校验合法管理资格/范围，不能因新管理员业务权限较小阻止必要撤回。
状态：用户已确认v2，事务/交接细则一并定稿；尚未开发对应写功能。
