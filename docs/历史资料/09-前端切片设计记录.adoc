== 实施边界与设计

沿用v2及五工作区，不再扩展菜单。admin应用独立页面承接真实数据，公共shell仅保留路由、会话、样式和OA/PMIS骨架。蓝灰#17324d导航、青绿#087f8c操作强调、#f2f5f8画布、#243746正文、#d8e1e8分隔；沿用中文系统字体。组织树/人员表、角色列表/详情标签作为主体，编辑用可键盘操作的模态表单，预览确认展示业务差异而非原始JSON或预览令牌。

本次接入已有组织/人员/账号的新增、查询、编辑、启停，角色基本信息/权限/成员，人员按应用角色集合/维护责任/有效权限，委派及组织/岗位原子换角，平台审计只读。没有物理DELETE接口；删除语义继续采用停用对象或移除授权关系。资源目录只读，导入、资源CRUD和OA/PMIS业务不在本次。

补齐两个阻碍表单的只读契约：平台按人员查询账号、应用管理范围内的组织名称选择目录（含必要祖先；不暴露人员或计数）。修正OpenAPI可空引用的生成结果。先改契约/测试设计再实现，不改V1–V3或引入第二份手写DTO。业务管理员只能通过本应用people接口选维护对象，不能调用全公司员工/账号/审计接口；平台按钮同时校验me中的资格及具体动作。

== 表单与一致性

所有写入共用Cookie/CSRF客户端，获取当前token，不自动重试写请求。401转登录；403解释管理范围；409保留编辑内容，要求回读后重新预览；503表示结果尚需回读确认，禁止盲目重放。编辑携带原expectedVersion，跨对象/应用切换先处理未保存内容，异步请求以序号/AbortController阻止旧响应覆盖。

角色权限和人员授权使用后端预览→确认；成员移除及启停明确显示影响。时间用Asia/Shanghai录入/展示后转UTC毫秒，[from,to)且结束排他。管理员失权/交接不改变员工旧权限的说明随相关表单展示。一次性临时密码仅在当前模态显示，关闭即清除，不进入URL、本地存储、日志、截图或测试报告。

== 验证设计

真实浏览器测试使用隔离MySQL/Redis后端与合成数据，验证登录→创建组织/人员/账号→创建角色→配置权限预览确认→分配/撤回角色→业务访问变化→委派/受限管理员管理→启停/编辑→审计回读。另验证401、403、409、空列表、组织范围、手机宽度及无页面错误。宿主数据库仅保留用户可测试的合成演示数据，浏览器测试不清理或修改用户既有数据；任何演示初始化只首次创建，不在重启时恢复权限。

完成时执行前端verify、相关真实后端集成、全量必要检查、文档渲染和浏览器截图审阅；实际证据统一更新plan/verification。不得以合成API响应或仅类型检查冒充CRUD联动成功。
