== 契约与范围（编码前设计）

沿用已确认v2，保留第一切片未提交修改；不修改已应用V1/V2。先扩充唯一OpenAPI，再新增V3和后端测试/实现。交付角色、角色权限、成员、应用管理员委派、人员维护责任、有效权限来源和人员原子换角；前端管理写表单、完整资源目录CRUD、导入、OA/PMIS业务、缓存/outbox及组织树重构授权影响分析不纳入本次。
含已授权人员的组织移动继续409保护，不能因为已有角色表就跳过组织移动的独立影响分析。岗位/主要组织变动使用本次新增预览→确认的原子换角，不经普通人员PUT绕过。

== 模型与兼容

V3将角色区分PLATFORM、COMMON、SCOPED、LEGACY。普通业务角色归属单应用；PLATFORM仅admin，COMMON/SCOPED仅业务应用，SCOPED有维护责任管理员及人员适用范围。旧bootstrap跨应用角色保留受保护LEGACY，只兼容演示/引导，不成为普通业务模板；旧demo角色明确回填应用，原登录权限不减少。
新增角色/角色权限组织范围、应用授权版本锁、管理员委派及组织/通用角色/权限上限/管理动作关联、人员每应用责任、人员每应用授权版本、通用变更预览。所有关联使用FK RESTRICT并显式维护，不级联删除用户角色。
管理动作显式保存在平台控制的委派动作关联，业务管理员固定只具备角色读取/专用角色维护/成员与授权维护等本应用动作；不能通过业务权限获得平台管理资格，不能修改自己的委派。权限核心统一解析角色权限和委派管理动作，经同一个PermissionChecker接入Spring方法授权。

== 授予与范围规则

新增/扩大权限同时被平台委派上限及操作者当前有效业务权限覆盖；已有保留部分不追溯裁剪，纯撤回不要求操作者本人拥有被撤回权限。新授角色校验完整权限定义，修改角色只校验新增点、扩大数据范围或延长时间所增加的部分；重新启用角色作为权限恢复，须校验全部定义。
SELF按目标用户解释，与指定组织范围分别表示；为避免历史本人记录跨组织，不能用有限ORG范围自动证明覆盖SELF。ALL覆盖所有模板；ORG不能冒充可覆盖未来后代的ORG_SUBTREE。当前多角色数据范围可取并集，范围检查保留模板及祖先关系，不只比较当前组织ID集合。
COMMON由平台维护；SCOPED由其责任管理员维护，且必须覆盖完整适用人员范围。存在非本人维护人员或管理员成员时，业务管理员不能编辑该角色定义或状态。业务管理员不能给自己或其他当前/未来管理员改业务角色。平台为业务管理员配置业务角色使用COMMON，避免通过自己维护的专用角色间接自提权；委派启用前校验其未持有SCOPED角色。
人员维护责任在每应用唯一，只影响谁可维护；丢失/过期/待接管不进入业务授权有效性判断。过期或账号停用由只读视图即时显示AWAITING，无需等待后台任务；写配置前固化已失效责任，续期/重新启用不自动取回待接管人员。管理员失权、委派撤销、范围缩减和维护交接均不撤其他人的用户角色；超出新管理范围的责任标记待接管。
已有角色被转交给较低业务权限的新管理员时不裁剪旧权限，后续新增授权仍按接管人当前上限检查。转交专用角色及其成员维护责任需平台预览/确认，范围必须可覆盖，原成员关系与授予历史不改写。员工持多个专用角色时允许分步交接；角色维护人暂不一致则人员维护责任待接管，最后一个相关角色完成交接后恢复CURRENT，整个过程不要求先撤员工角色。

== 事务与预览

授权写先持组织目录共享锁，再按顺序持admin命名空间共享锁/目标应用独占锁、必要的最后管理员保护锁和主体锁；不同业务应用可独立更新，不使用全局授权写锁。人员全应用换角因改组织资料，持目录独占锁并按应用ID顺序锁定全部相关命名空间。
角色权限、人员角色集合、角色责任转交和人员换角均用服务端15分钟预览，绑定操作者、类型、目标、目标版本、组织版本和应用授权版本；确认时重新校验当前权限及范围。失败/过期/重放/版本变化不写入。数据变更、版本增加、预览消费和脱敏审计同事务提交。
人员换角一次性撤回本人旧角色并配置各应用新角色、组织/岗位及明确的KEEP/RETIRE管理任职选择；允许明确空新角色集合。新角色校验、管理资格或最后管理员保护失败则全部回滚。其他员工角色完全不变，管理员离任后的人员责任待接管而不失去业务访问。
角色成员移除无此关系时幂等成功，仍校验操作者资格/范围；批量成员最多100人且任一越界整批拒绝。授权版本按人员+应用分别维护，覆盖修改使用expectedVersion。
